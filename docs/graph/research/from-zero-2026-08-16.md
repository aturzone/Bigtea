## What a fresh machine needs

| | |
|---|---|
| Rust | 1.82+. On Windows the **GNU** toolchain: `rustup default stable-x86_64-pc-windows-gnu` |
| Windows only | MSYS2 with `mingw64/bin` on PATH, **to build, not to run** |
| ggml | built once, `ggml-base.a` + `ggml-cpu.a` + `ggml.a`, pointed at by `GGML_LIB_DIR` |
| GPU work | a **second** ggml build with `-DGGML_VULKAN=ON`, in its own directory |
| disk | nothing beyond the checkout; models are the user's own |
| network | none, after the clone |

**Clean clone to running binaries: 23 s.** 566 tests, 0 failed. Twelve binaries.

## The build message when `GGML_LIB_DIR` is absent is the one that matters

Nine of the ten crates build without it — the container parser, hardware probe,
planner, I/O layer, model resolver, tokenizer, grammar, template engine and the
FFI crate itself. Only `chaos-arch` needs it, and it says so:

```
$ cargo build --release -p chaos-arch     # GGML_LIB_DIR unset
  cargo:warning=       export GGML_LIB_DIR=/path/to/llama.cpp/build/ggml/src
  cargo:warning=       $env:GGML_LIB_DIR = "C:/path/to/..."   # PowerShell
  cargo:warning=  Full instructions: https://github.com/aturzone/Chaos#building
  thread 'main' panicked at crates/chaos-arch/build.rs:118:5:
  ggml not found -- see the instructions above
```

One actionable message rather than a wall of unresolved imports. CI asserts this
holds, and this run gained `chaos-jinja` to the ggml-free job — the README
claimed nine of ten and the job was proving eight.

## Two things surprise a first-time user, and only one is a bug

### 1. The first GPU run is four times slower than the second

`--auto` on Qwen3-4B, on a machine that had never run this binary:

```
generated  12 tokens in 7.4s (1.63 tok/s)
```

Against **6.85 tok/s** for the same model with no flags. That reads as `--auto`
being catastrophically wrong, and it was nearly written down as such.

It is not. Alternating four pairs on a warm machine:

| round | default | `--auto` |
|---|---:|---:|
| 1 | 7.57 | **9.20** |
| 2 | 7.84 | **9.63** |
| 3 | 7.47 | **9.00** |
| 4 | 7.24 | **9.46** |

**`--auto` is 1.23x ahead, in four pairs of four.** The 1.63 was ggml's Vulkan
backend compiling its shader set inside the timed region on first use; the driver
then persists the pipelines to disk and every later run is a different program.
`CLAUDE.md` already carries this rule — *"discard the first run"* — bought by a
published figure that had to be retracted. It caught this one.

**It is still a real user experience.** The first `chaos-run --auto` after an
install is slow, once, and nothing says why. That is worth a line in the CLI and
is not yet written.

### 2. The demo model refuses to run

```
$ chaos-run Qwen3-30B-A3B-Q4_K_M.gguf "..." --auto
chaos-run: "qwen3moe" is not an architecture this build has been verified against.
           verified: baichuan, gemma, deepseek4, gemma2, gemma3, internlm2,
                     llama, olmo, phi3, qwen2, qwen3, stablelm, starcoder2
           It may load and generate, and be WRONG with no error.
           Pass --force to run it anyway.
```

**This is correct and deliberate** — `qwen3moe` scores 2 exact, 4 near-tie and 2
outside the band on the eight-prompt sweep, so it is off the verified list on
purpose. But it is also the model this project's best numbers are measured on and
the one a new user is most likely to try, so the refusal has to be documented
rather than discovered.

## `--auto`'s decisions, and they are the right ones

On the dense model that fits:

```
device     1 (Vulkan1): the whole model is 2.3 GiB against 4.1 GiB usable VRAM
           -- offloading all of it
device     1, all blocks resident on it
```

On the MoE model that does not:

```
device     none: 17.3 GiB of model against 4.1 GiB usable VRAM, and this model
           streams experts. Measured 4.3x SLOWER offloaded (2.61 -> 0.61 tok/s),
           so the card is left alone
cache      5.0 GiB of experts (half of 10.0 GiB free, capped at the 6 GiB plateau)
```

It refuses the card **with the measurement in the message**, which is the
behaviour `gpu-does-not-help-streaming-moe-2026-08-16.md` asked for. It also
picks the two Vulkan devices apart correctly, choosing the discrete RTX 3050 over
the Intel integrated controller.

**One fix came out of this run.** The cache line printed on *dense* models too —
`cache 8.41 GiB for experts` under a 2.3 GiB model with no experts at all, which
reads like the runner is about to allocate three times the model. Harmless
(nothing streams, so the budget is a ceiling on an empty cache) and alarming, and
it is the first line a new user sees under `--auto`. Now printed only when the
model has routed experts.

## One methodological note, which cost this run twice

The first attempt cloned from the **local** repository and got a tree nine
commits old, because that repository's `main` had never been fast-forwarded and
`git clone --branch main` takes it at its word. The build failed with
`package ID specification 'chaos-arch' did not match any packages` — which is the
clearest possible symptom and was still confusing for a minute. **Clone from the
remote when the point is to test what a stranger gets.**
