- research/zero-copy-expert-reads.md — **T0.1, resolved.** The "1.06 GiB/s disk" in a V4-Flash prefill was 34-36% memcpy: every expert byte was copied three times (`.to_vec()` in `read_at`, `extend_from_slice` into the stack, `Arc<[u8]>::from` in `bind`). Behind that sat a bigger finding — **GGUF pads tensor data to 32 bytes, not to a sector**, so V4-Flash's experts start at file offset ≡ 2816 (mod 4096) and *no* conventionally-aligned buffer can ever receive a direct transfer. Deliberately skewing the destination by the same 2816 (`SkewedBuf`) makes the residues agree: 0.80 → 1.58 GiB/s with 0.09% of bytes copied, and **1.38x end-to-end on the real model** (32.4s → 23.7s prefill, same token, all 14 forward tests still matching llama.cpp) — links: v4flash-speed-budget.md, ../backlog/lts-0-0-0.md
